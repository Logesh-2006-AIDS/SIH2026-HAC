OVERVIEW:
This document outlines the step-by-step technical implementation roadmap for 
building the AI-Powered Criminal Network Analysis Platform for law-enforcement 
investigators.

--------------------------------------------------------------------------------
PHASE 1: PROJECT SCAFFOLDING & ENVIRONMENT SETUP
--------------------------------------------------------------------------------
Goal: Establish project architecture, virtual environments, database services, 
and dependencies.

1.1 Repository Structure Setup
    - Create backend/ directory (FastAPI, Python)
    - Create frontend/ directory (React.js, Cytoscape.js)
    - Create data/ directory with synthetic crime records (FIRs, CDRs, Financial logs)
    - Create docker/ configuration files and docker-compose.yml

1.2 Backend Environment & Dependencies
    - Python 3.10+ virtual environment
    - Core dependencies: fastapi, uvicorn, neo4j, psycopg2-binary, sqlalchemy, 
      pydantic, spacy, sentence-transformers, networkx, python-jose, passlib

1.3 Database Setup
    - Neo4j graph database instance (Docker container)
    - PostgreSQL database instance (Docker container)
    - Database migration & schema setup scripts

--------------------------------------------------------------------------------
PHASE 2: SYNTHETIC DATA GENERATION & INGESTION PIPELINE
--------------------------------------------------------------------------------
Goal: Create realistic synthetic datasets and build the ingestion system.

2.1 Synthetic Dataset Design
    - Generate synthetic FIRs (unstructured text reports)
    - Generate CDR (Call Detail Record) CSVs (Caller, Receiver, Timestamp, Duration, Cell Tower)
    - Generate financial transaction logs (Sender, Receiver, Amount, Bank/Account, Date)
    - Multi-case scenario mapping (overlapping suspects, phone numbers, shell companies)

2.2 Ingestion Engine
    - Multi-format ingestion parsers (CSV, JSON, Plain text FIRs/reports)
    - Input validation, text normalization, and deduplication
    - Storage of raw ingestion payloads in PostgreSQL with audit timestamps

--------------------------------------------------------------------------------
PHASE 3: AI & NLP PROCESSING PIPELINE
--------------------------------------------------------------------------------
Goal: Extract entities, extract relations, perform entity resolution, and generate 
evidence-aware explainable scores.

3.1 Text Preprocessing & Cleaning Pipeline (backend/app/nlp/preprocessor.py)
    - Unicode normalization and legal text cleaning (FIR, BNS, IPC, CDR acronyms)
    - Document structure parsing (FIR headers, accused statements, seized property lists)
    - Sentence tokenization, custom legal stopwords, and noise filtering

3.2 Named Entity Recognition (NER) Engine (backend/app/nlp/ner.py)
    - Rule-based regex pattern matchers (backend/app/nlp/patterns.py):
      * Phone numbers (Indian formats: +91-XXXXX-XXXXX, 098XXXXXXXX)
      * Vehicle plates (Indian RTO: DL-01-AB-1234, MH12CD5678)
      * Financial accounts (9-18 digit account numbers, IFSC codes, UPI IDs)
      * Case / FIR numbers (FIR No. 101/2025 PS Crime Branch)
      * Dates & Timestamps (DD/MM/YYYY, ISO-8601)
    - Statistical / Transformer-based NER (spaCy en_core_web_sm / Hugging Face):
      * Person (suspects, victims, associates, aliases like "Ravi @ Ravan")
      * Organization (gangs, shell companies, front businesses)
      * Location (incident spots, hideouts, addresses, cell tower zones)
      * Event (meetings, extortion calls, transactions, robberies)
    - Entity deduplication, boundary validation, and confidence score calculation

3.3 Relationship Extraction (RE) Engine (backend/app/nlp/relationship_extractor.py)
    - Semantic triple extraction: (Subject Entity) -> [PREDICATE] -> (Object Entity)
    - Dependency parser tree traversal & rule-based pattern matching:
      * COMMUNICATES_WITH (calls, SMS, meetings, messages)
      * ASSOCIATED_WITH (gang associate, partner, syndicate member)
      * INVOLVED_IN (accused in FIR, suspect in case, witness)
      * LOCATED_AT (resident at, hideout at, cell tower ping)
      * OWNS (vehicle owner, phone subscriber, account holder)
      * FINANCIAL_TRANSFER_TO (NEFT, UPI, Hawala payment, cash handover)
      * APPEARED_IN (mentioned in surveillance report, informant tip)
    - Evidence anchoring: Attach source document ID, sentence offset, and excerpt 
      to every extracted relationship edge.

3.4 Entity Resolution & Record Linkage Engine (backend/app/nlp/entity_resolution.py)
    - Multi-tiered similarity matching for fuzzy aliases:
      * String & phonetic similarity: Jaro-Winkler, Levenshtein, Double Metaphone
      * Semantic embeddings: sentence-transformers (all-MiniLM-L6-v2) cosine similarity
      * Contextual overlap: Shared phone numbers, shared addresses, co-occurring cases
    - Candidate match generation (e.g., "Ravi Kumar" vs "R. Kumar" vs "Ravi K.")
    - Staging candidate matches in PostgreSQL for Human-in-the-Loop investigator review

3.5 Explainability & Confidence Scoring (backend/app/nlp/explainability.py)
    - Multi-factor scoring formula:
      Score = w1 * SemanticSim + w2 * PhoneticSim + w3 * ContextualOverlap
    - Evidence rationale generator (human-readable explanation of why entities/links match)

3.6 Pipeline Orchestrator & Benchmarking (backend/app/nlp/pipeline.py)
    - End-to-end pipeline: raw text -> cleaned text -> entities -> triples -> resolved entities
    - Automated benchmarking against ground truth data (Precision, Recall, F1 score)


--------------------------------------------------------------------------------
PHASE 4: KNOWLEDGE GRAPH & ANALYTICS ENGINE
--------------------------------------------------------------------------------
Goal: Construct the Neo4j Knowledge Graph and run graph algorithms.

4.1 Graph Construction & Indexing
    - Populate Neo4j nodes (Person, Org, Phone, Case, Location, etc.)
    - Populate directed, weighted edges with metadata (source case, confidence, timestamp)
    - Create Neo4j indexes (Node labels, full-text indexes, property indexes)

4.2 Centrality & Key Player Identification
    - Degree Centrality: Identify high-activity hubs (frequent communicators)
    - Betweenness Centrality: Identify key bridge entities / intermediaries between gangs or cases

4.3 Community Detection & Subgroup Discovery
    - Louvain / Leiden community detection algorithm
    - Cluster partition and sub-network tagging

4.4 Shortest Path & Connection Tracing
    - BFS / Dijkstra shortest path finder between any two specified entities
    - Multi-hop path explanation with edge-level reasoning

4.5 Link Prediction Engine
    - Uncover hidden links using Jaccard Similarity, Common Neighbors, and Adamic-Adar scores
    - Cross-case connection detection (entities appearing across distinct cases)

--------------------------------------------------------------------------------
PHASE 5: FASTAPI BACKEND & SECURITY LAYER
--------------------------------------------------------------------------------
Goal: Build robust REST and WebSocket APIs with RBAC and explainability endpoints.

5.1 Security, Authentication & RBAC
    - JWT authentication with secure password hashing (bcrypt)
    - Role-Based Access Control: Admin, Investigator, Analyst, Viewer
    - Tamper-evident audit logging for all search, view, and verification operations

5.2 Graph & Query APIs
    - GET /api/graph/subgraph (filtered by case, entity type, confidence, date range)
    - GET /api/graph/entity/{id}/details (entity metadata, connections, evidence source)
    - GET /api/graph/path?source={id}&target={id} (shortest path analysis)
    - GET /api/graph/centrality (ranked influential entities)
    - GET /api/graph/communities (detected clusters)

5.3 Lead Management & Human-in-the-Loop APIs
    - GET /api/leads/pending (AI-suggested link predictions and resolved entities)
    - POST /api/leads/{id}/verify (Accept, Reject, Edit, Merge with investigator remarks)
    - GET /api/leads/cross-case (prioritized cross-case connectors)

5.4 Explainability & Search Engine
    - Natural language query / keyword search across entities and cases
    - Evidence builder providing source references, confidence formulas, and path explanations

--------------------------------------------------------------------------------
PHASE 6: FRONTEND INVESTIGATOR WORKBENCH (REACT.JS)
--------------------------------------------------------------------------------
Goal: Deliver an interactive, modern, high-performance UI with graph visualization.

6.1 Interactive Graph Canvas (Cytoscape.js)
    - Color-coded node taxonomy (Person=Blue, Phone=Cyan, Org=Orange, Case=Gold, Location=Red)
    - Interactive pan, zoom, drag, expand node on click, and highlight connected subgraphs
    - Layout toggles: Force-directed (CoSE / FCose), Concentric, Breadth-First, Circular

6.2 Investigation Control Panels
    - Dynamic Filters: Filter by Case ID, Date Range, Confidence Score, Relationship Type
    - Entity Details Inspector: Side drawer showing properties, source evidence, centralities
    - Path Finder Modal: Select two entities to highlight shortest chain of connections

6.3 Cross-Case & Lead Verification Center
    - Visual comparison view between two or more cases
    - Lead Verification Workbench: Accept / Reject / Merge AI suggestions
    - Audit Trail & Case Report Export view

--------------------------------------------------------------------------------
PHASE 7: TESTING, VALIDATION & DOCKER DEPLOYMENT
--------------------------------------------------------------------------------
Goal: Validate algorithm accuracy, security constraints, and containerize the stack.

7.1 End-to-End Testing
    - Test synthetic data pipeline through ingestion, extraction, graph creation, and UI
    - Verify link prediction confidence calculations and explainability outputs
    - RBAC access control validation tests

7.2 Dockerization & Orchestration
    - Multi-stage Dockerfiles for Backend and Frontend
    - Complete docker-compose.yml orchestrating:
      * FastAPI backend
      * React frontend
      * Neo4j DB
      * PostgreSQL DB
      * Redis cache
